# Phase 1 — Brief

Goal: lock the brief before any drafting. Three questions up front beat three redrafts later.

## What the user may bring

Any subset of: theme, context, thesis, conclusion, target audience, working title, proof points, references. Take everything offered; ask only for what's missing.

## The kick-off questions (ask what the brief doesn't answer)

1. **Core argument** in one or two sentences. If the user has a predetermined conclusion, capture it verbatim; the article's destination is theirs, you structure the route.
2. **Audience** — be specific. "Security-conscious businesses" beats "everyone"; "MSPs" and "product people & hiring managers" produce very different articles. Also ask for the *secondary* audience.
3. **How this fits the bigger picture** — work, side project, job-hunt positioning, follow-on to previous content? If follow-on, decide the callback style now.
4. **Desired outcome** — comments and conversation? Authority? Inbound? This determines the close (open question vs CTA).
5. **Vendor/employer positioning** — none, nod, or explicit. (Check `profile/context.md` for the default; confirm, don't re-interrogate.)
6. **Register and length band** for THIS piece — read the Registers section of `profile/voice-profile.md` and ask which named register applies (offer them as choices), or whether this piece needs a new one. Mechanics (punctuation, banned words, density limits) are absolute regardless of register; only the register's flex dimensions change. If a new register is minted, add it to the profile with the user's approval.
7. **Anchors already in mind** — lived experiences, a Reddit thread, a framework, a historical parallel, project artefacts.
8. **The one line a reader should repeat to a colleague.**

Use short multiple-choice questions where the platform supports them. Two or three well-chosen questions at a time; don't interrogate.

## Known failure mode: the late audience pivot

Audience has repeatedly turned out to be a late-stage decision, forcing rework after a "final" draft. Countermeasure: ask the audience question **twice** — here, and again immediately before the voice edit (Phase 5). Budget for the possibility that it changes.

## Output

Write `articles/<slug>/brief.md`: argument, conclusion, audiences (primary/secondary), fit-to-bigger-picture, outcome, positioning, tone/length, anchors, repeat-line, and callback plan if any. Get the user's sign-off on the brief before moving to research.
